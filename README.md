# 定稿AI · 研究生论文AI辅助系统（v0.5.1 · 本地优先架构）

> 写论文，用谁家都行；交稿之前，先定稿。

## 🎯 这个项目解决什么问题

写论文最耗时的往往不是「写」，而是**交稿前的收尾**：排版格式、引用核查、参考文献互译、格式检查……这些机械工作没有一款现成工具能一站式覆盖。**定稿AI** 面向研究生提供写作全流程辅助：

- **写作前半场**：AI 辅助选题（六要素＋追问迭代）→ AI 生成大纲（树状编辑）→ 本地编写＋Word 备份 → 进度打卡
- **交稿核查场**：中英文献互译（学术语体）＋ 交稿检查报告（引用核查＋docx 格式检查，只检不改）
- **隐私设计（本地优先）**：论文全文**只存在你自己的浏览器**（IndexedDB 按账号分库）——服务端零论文存储、AI 输入仅内存中转不落盘，服务器被攻破也拿不到任何论文内容

范围对应《R8 定稿AI-产品待办事项列表与完工定义(DoD)-V1.3》的 7 项 Must：选题（M9）/ 大纲（M10）/ 本地编写（M11）/ 进度打卡（M12）/ 互译（M4）/ 交稿检查（M8）/ 工程地基与测试资产。v0.2 的引用核查/分段校对按 V1.3 降级保留（S7/S8）。

## 🏛️ 架构一览（本地优先）

```
┌────────── 用户浏览器 ────────────┐    ┌──────── 服务器（本机/局域网/任意云） ────────┐    ┌── DeepSeek ──┐
│ IndexedDB 按账号分库             │    │ 登录/会话/记录（SQLite）                     │    │              │
│   论文 · 大纲 · 进度 · 打卡      │ ─► │ 用户Key（AES-256-GCM 加密存储）             │ ─► │ deepseek     │
│ Word导出（浏览器本地生成 docx）  │    │ 选题/大纲/互译/校对 AI 中转（输入不落盘）   │    │ v4-flash     │
│ 引用核查/交稿检查（规则引擎,0AI）│ ◄─ │ 限流 60次/时 · 文档三件套 · 投诉/注销       │    │              │
└─────────────────────────────────┘    └──────────────────────────────────────────────┘    └──────────────┘
```

**论文全文/大纲/进度/打卡只存用户浏览器 IndexedDB**（按账号分库）——服务端零论文存储，AI 输入仅内存中转不落盘，Word 导出在浏览器端完成。代价：换设备/清浏览器数据后不可见（Word 导出兜底）；红利：服务器被攻破也拿不到任何论文内容，可放心部署任意云。

## 🚀 快速开始

双击 **`启动定稿AI.bat`**（推荐）——自动：①检测服务是否已在运行 ②添加防火墙放行规则（首次会弹 UAC，点"是"，仅需一次）③启动服务（异常退出 3 秒自动重启）④打开浏览器。

或手动：

```bash
npm install            # Node ≥ 22（node:sqlite 内置）
node server.js         # 密钥读取：环境变量 DEEPSEEK_API_KEY > DINGAO_KEY_FILE 指定文件 > config/key.txt
```

- 本机访问：http://localhost:8788
- 局域网访问：**以服务窗口输出的地址为准**（登录页与侧边栏底部也会动态显示当前局域网地址——路由器 DHCP 换 IP 后自动更新）
- 首个注册账号自动成为管理员（可用平台 Key）；普通用户在「我的Key」配置自己的 DeepSeek Key（保存前本地核对，AES-256-GCM 加密落库，前端只显示掩码）

### 密钥配置（AI 功能）

服务端读取优先级：环境变量 `DEEPSEEK_API_KEY` → 环境变量 `DINGAO_KEY_FILE` 指定的文件 → `config/key.txt`（一行 `sk-...`，已 gitignore）。详见 `config/README.md`。

### 关于 .bat 脚本

三个 .bat 为 **GBK 编码**（Windows cmd 中文环境原生编码）——在 GitHub 网页预览可能显示乱码，属正常现象；克隆到 Windows 后双击即可正常使用。`启动内网穿透.bat` 中 cpolar 路径以 `%USERPROFILE%` 表示（首次使用需先注册 cpolar 账号并执行 authtoken 认证）；如 cpolar 安装在其他位置请按需修改。

### 常见问题：网址打不开 / 其他电脑连不上

1. **服务没在运行**（最常见）：主机关机/窗口被关后服务即停止。解决：双击「启动定稿AI.bat」；可向产品组申请开机自启脚本（需你确认后安装）。
2. **防火墙拦截**（其他电脑连不上）：运行 bat 时会自动放行 TCP 8788；或手动以管理员执行：
   `netsh advfirewall firewall add rule name="dingao-ai-8788" dir=in action=allow protocol=TCP localport=8788`
3. **IP 变了**：局域网地址以登录页显示为准；建议在路由器把本机 MAC 绑定为固定 IP。
4. **登录态**：会话有效期 30 天，存于本机数据库，服务重启不清除。

### github.io 静态镜像

`public/app.js` 顶部 `REMOTE_API` 用于 github.io 静态镜像：**部署前填你自己的公网后端地址**（默认为空）；当页面运行在 `github.io` 域名下时，前端自动跨域调用该后端；本地/局域网访问不受影响（同源调用）。gh-pages 分支只含 public/ 静态文件，作为纯前端镜像部署。

## 🏗️ 技术栈

- **后端**：Node.js + Express + node:sqlite（零原生依赖）；SSE 事件协议；选题/大纲走非流式 JSON（response_format=json_object + 尽力解析）
- **AI**：DeepSeek API（deepseek-v4-flash；v4-pro 易超时、v0.5 起移除 UI 入口）；**不设 max_tokens**（V4 推理模型思考与答案共用输出预算，显式小值会饿死答案）
- **前端**：原生 HTML/CSS/JS（无构建步骤）；左侧分组导航（写作辅助/文献工具/交稿核查/我的）＋写作四视图＋工具工作区；响应式（≤1100px 侧栏收窄）
- **文档**：docx 库（导出）、adm-zip（docx 导入＋格式元数据）、pdf-parse（PDF 文本层）

## 🔒 合规红线（V1.4）

1. **内容0修改**：AI 只辅助不改写论断；校对「整篇一键修正」不提供，逐条确认后由用户应用（可撤销）；AI 结果标注需人工核验
2. **论文隐私（V1.4·本地优先）**：论文全文/大纲/进度/打卡仅存用户浏览器 IndexedDB（库名按账号隔离 `dingao_v04_<用户id>`）；服务端数据库只有 users/sessions/api_keys/records 四张表，没有任何论文数据表与存储端点；AI 调用输入仅内存中转不落盘
3. **数据最小化**：服务端仅存账号/会话/密钥/用户主动保存的工具结果记录
4. **密钥安全**：DeepSeek 密钥仅存服务端（AES-256-GCM）
5. **限流**：每用户 60 次 AI 请求/小时

> ⚠️ 本地存储提示：论文存在浏览器里，换电脑/换浏览器/清空浏览器数据将看不到（可随时导出 Word 备份）；Safari 隐私模式下 IndexedDB 受限，请使用普通模式。

## 🔑 提交前密钥扫描（pre-commit 钩子）

仓库自带提交前扫描钩子（`.githooks/pre-commit`，经 `core.hooksPath` 生效），每次 `git commit` 自动拦截：

1. **敏感文件**：`*.db` / `secret.key` / `key.txt` / `.env` / `*.pem` / `cpolar.yml` 等——即使 `git add -f` 强行添加也会被拦下
2. **暂存内容中的密钥格式**：DeepSeek `sk-` 密钥、GitHub PAT、AWS/Google API Key、SSH 私钥等常见格式

- 新克隆后启用：`git config core.hooksPath .githooks`
- 确属误报时：`git commit --no-verify`（慎用——公开仓库的提交不可撤回）

## 💎 开发心得（真实踩坑记录）

1. **DeepSeek V4 是推理模型**：`reasoning_content` 与答案**共用输出预算**——显式设 `max_tokens` 会让思考耗尽预算、答案为空（实测：设 8192 时 2500 字块 0.4 秒返回空输出；不设时 0.8 秒输出 4908 字）。正确做法：**不设 max_tokens + 输入 ≤2500 字切块**。
2. **V4 流式通道不稳定**（内容在 reasoning_content 且收尾不稳）：AI 请求采用**非流式获取 + 服务端切块 SSE** 推给前端，兼顾稳定与实时体验；单块失败不阻塞其余块、可重试。
3. **Windows 批处理铁律**：.bat 必须 **CRLF 行尾 + GBK 编码**——LF 行尾会让 cmd 乱解析，报「不是内部或外部命令」。
4. **SSE 与反向代理**：反代（Caddy 等）需关闭缓冲（`flush_interval -1`），否则流式输出被攒批。
5. **Express 路由顺序**：具体路由必须先于通配路由注册，否则被吞（`/api/ai/proofread` 曾 400，因先注册的 `/api/ai/:task` 截胡）。
6. **docx 库双打包坑**：同一 Document 只能 `Packer.toBuffer` 一次（内部关系表会被改写），双打包 = Word 拒开。
7. **加密与前端实践**：AES-256-GCM 加解密显式 `authTagLength: 16`；前端无构建（原生 JS），`api.req` 统一封装 JSON/流式/超时/错误横幅。
