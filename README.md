# 定稿AI · 研究生论文AI辅助系统（v0.5.1）

> 写论文，用谁家都行；交稿之前，先定稿。

## 🎯 这个项目解决什么问题

写论文最耗时的往往不是「写」，而是**交稿前的收尾**：排版格式、引用核查、参考文献互译、格式检查……这些机械工作没有一款现成工具能一站式覆盖。**定稿AI** 面向研究生提供写作全流程辅助：

- **写作前半场**：AI 辅助选题（六要素＋追问迭代）→ AI 生成大纲（树状编辑）→ 本地编写＋Word 备份 → 进度打卡
- **交稿核查场**：中英文献互译（学术语体）＋交稿检查报告（引用核查＋docx 格式检查，只检不改）
- **隐私设计（本地优先）**：论文全文**只存在你自己的浏览器**（IndexedDB 按账号分库）——服务端零论文存储、AI 输入仅内存中转不落盘，服务器被攻破也拿不到任何论文内容

## ✨ 核心功能

| 功能 | 说明 |
|---|---|
| 🎯 选题助手 | 实际问题表单 → AI 生成 3-5 个选题（题目/研究问题/创新点/与文献关系/可行性/推荐理由六要素）→ 会话追问迭代 → 一键采纳并生成本地章节结构 |
| 📑 大纲生成 | AI 生成章-节两级大纲（纯中转不落盘）；树状编辑（增删改/上下移/升降级/改名）；txt/docx 导出 |
| 📝 本地编写 | 按章节写作、自动保存到本浏览器 IndexedDB（900ms 防抖）；一键导出全文 Word 备份（浏览器端生成，超 7 天未导出提醒）；**论文内容不经过服务器** |
| 📊 进度打卡 | 章节字数/完成状态、全文进度条、目标字数；每日打卡与连续打卡天数；全部本地计算，零 AI 成本 |
| 🌏 中英互译 | DeepSeek 流式，学术语体，撤销栈保留 7 次 |
| 📋 交稿检查报告 | 引用核查＋docx 格式检查（页边距/字体/字号/行距/标题层级/页码），只检不改，零 AI 成本 |
| ✅ 分段校对 | 智能分段（≤2500字/块）逐块校对＋SSE 进度＋单块重试＋逐条确认应用 |
| 🔗 引用核查 | 序号错位检出＋一键重排建议＋重复识别；GB/T 7714 / APA 7th / MLA 9th |

## 🚀 如何运行

**方式一（Windows 推荐）**：双击 **`启动定稿AI.bat`** —— 自动完成：①检测服务是否已在运行 ②添加防火墙放行规则（首次弹 UAC 点「是」，仅一次）③启动服务（异常退出 3 秒自动重启）④打开浏览器。

**方式二（手动）**：

```bash
npm install            # Node ≥ 22（node:sqlite 内置）
node server.js         # 访问 http://localhost:8788
```

- 局域网访问：以服务窗口输出的地址为准（登录页与侧边栏底部动态显示；路由器 DHCP 换 IP 后自动更新）
- **AI 功能需密钥**：服务端读取优先级 = 环境变量 `DEEPSEEK_API_KEY` → 环境变量 `DINGAO_KEY_FILE` 指定文件 → `config/key.txt`（一行 `sk-...`，已 gitignore，详见 `config/README.md`）；用户也可登录后在「我的Key」配置自己的 DeepSeek Key（保存前本地核对，AES-256-GCM 加密落库，前端只显示掩码）
- 首个注册账号自动成为管理员（可使用平台密钥）
- 三个 .bat 为 **GBK 编码**（Windows cmd 原生编码）——GitHub 网页预览显示乱码属正常，克隆到 Windows 后双击即可用
- 常见问题：网址打不开=服务没在运行（双击 bat）；其他电脑连不上=防火墙（bat 自动放行 TCP 8788）；IP 变了=以登录页显示为准

## 📂 项目主要结构

```
dingao/
├─ server.js          # 后端（认证/写作四模块/互译/校对/规则引擎/记录/导入导出）
├─ public/            # 前端（原生 HTML/CSS/JS，无构建步骤）
├─ test/              # 自动化测试（9 套件 102+ 断言）与测试计划、黄金集
├─ .githooks/         # pre-commit 密钥扫描钩子（core.hooksPath 指向此处）
├─ config/            # 私有配置（key.txt / secret.key，勿提交；README.md 有说明）
├─ 启动定稿AI.bat      # 启动脚本（防火墙放行＋看门狗自动重启＋开浏览器）
├─ 自启动服务.bat      # 开机自启辅助脚本（可选安装）
└─ dingao.db          # SQLite（自动创建；仅存账号/会话/密钥密文/工具记录——论文内容不在其中）
```

**架构一句话**：浏览器 IndexedDB（论文数据）↔ Node 服务端（账号与 AI 中转）↔ DeepSeek API —— 本地优先，服务端零论文存储。

## 💎 开发心得（真实踩坑记录）

1. **DeepSeek V4 是推理模型**：`reasoning_content` 与答案**共用输出预算**——显式设 `max_tokens` 会让思考耗尽预算、答案为空（实测：设 8192 时 2500 字块 0.4 秒返回空输出；不设时 0.8 秒输出 4908 字）。正确做法：**不设 max_tokens + 输入 ≤2500 字切块**。
2. **V4 流式通道不稳定**（内容在 reasoning_content 且收尾不稳）：AI 请求采用**非流式获取 + 服务端切块 SSE** 推给前端，兼顾稳定与实时体验；单块失败不阻塞其余块、可重试。
3. **Windows 批处理铁律**：.bat 必须 **CRLF 行尾 + GBK 编码**——LF 行尾会让 cmd 乱解析，报「不是内部或外部命令」。
4. **SSE 与反向代理**：反代（Caddy 等）需关闭缓冲（`flush_interval -1`），否则流式输出被攒批；反代与静态站点同域时，`/api` 反代要放进 `handle /api/*` 互斥块，否则会被 `try_files` 拦截（GET 返回首页 HTML、POST 405）。
5. **Express 路由顺序**：具体路由必须先于通配路由注册，否则被吞（`/api/ai/proofread` 曾 400，因先注册的 `/api/ai/:task` 截胡）。
6. **docx 库双打包坑**：同一 Document 只能 `Packer.toBuffer` 一次（内部关系表会被改写），双打包 = Word 拒开。
7. **加密与前端实践**：AES-256-GCM 加解密显式 `authTagLength: 16`；前端无构建（原生 JS），`api.req` 统一封装 JSON/流式/超时/错误横幅。

## 🔒 合规设计要点

- **内容 0 修改**：AI 只辅助不改写论断；校对逐条确认后由用户应用（可撤销）；AI 结果标注需人工核验
- **论文隐私（本地优先）**：论文全文/大纲/进度/打卡仅存用户浏览器；服务端数据库只有 users/sessions/api_keys/records 四张表，没有任何论文数据表与存储端点
- **密钥安全**：DeepSeek 密钥仅存服务端（AES-256-GCM）；仓库自带 pre-commit 钩子拦截密钥与敏感文件（`.githooks/`，新克隆后 `git config core.hooksPath .githooks`）
- **限流**：每用户 60 次 AI 请求/小时
- ⚠️ 论文存在浏览器里：换电脑/换浏览器/清空浏览器数据将看不到（可随时导出 Word 备份）；Safari 隐私模式 IndexedDB 受限，请用普通模式
